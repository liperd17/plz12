# Review Code

구현된 코드를 검토하고 문제점과 개선 방법을 제안한다.

## 작업 절차

1. AGENTS.md와 사용자 요구사항을 확인한다.
2. 구현된 코드와 관련 파일을 확인한다.
3. 사용자 요구사항대로 기능이 구현되었는지 검토한다.
4. 버그가 발생할 수 있는 부분을 확인한다.
5. 기존 기능에 문제가 생길 가능성이 있는지 검토한다.
6. 발견한 문제와 개선 방법을 정리한다.

## 검토 결과 형식

### 종합 평가
코드의 전반적인 상태를 간단히 설명한다.

### 발견한 문제
문제마다 다음 항목을 작성한다.

#### 문제 1: [문제 요약]
- **핵심 위치:** 실제 파일 경로, 관련 함수·메서드 이름, 확인한 줄번호 또는 문제를 찾을 수 있는 짧은 코드 구간
- **관련 위치:** 여러 파일이 연결된 문제라면 원인이나 동작에 관련된 파일·함수·코드 위치를 구분해 기재한다. 관련 위치가 없으면 `없음`으로 쓴다.
- **발생 조건 및 영향:** 문제가 발생하는 조건과 실제 동작에 미치는 영향
- **근거:** 확인한 코드와 사용자 요구사항을 연결해 문제가 되는 이유를 설명한다.
- **중요도:** 높음 / 보통 / 낮음
- **개선 제안:** 문제를 해결할 구체적인 방법

필요한 만큼 문제 항목을 반복한다.

### 개선 제안
발견한 문제를 어떻게 해결하면 좋을지 설명한다.

### 최종 의견
추가 수정이 필요한지 판단한다.

## 규칙

- 코드 검토 단계에서는 코드를 수정하지 않는다.
- 실제 코드와 사용자 요구사항을 근거로 검토한다.
- 확인하지 않은 문제를 사실처럼 설명하지 않는다.
- 파일 경로와 함수·메서드 이름은 실제 코드에서 확인한 값으로 작성한다.
- 줄번호는 현재 파일을 직접 확인한 경우에만 기재한다. 줄번호를 확인할 수 없다면 그 사실을 밝히고 함수·메서드 이름이나 짧은 코드 구간으로 위치를 안내한다. 줄번호를 추측하지 않는다.
- 문제의 위치는 실제 파일 경로와 함께 제시한다. 여러 파일이 연결된 문제는 핵심 위치와 관련 위치를 구분한다.
- 각 문제에 발생 조건, 실제 영향, 코드와 요구사항에 근거한 이유, 중요도 및 개선 제안을 포함한다.
- 사소한 코드 스타일보다 실제 동작에 영향을 주는 문제를 우선한다.
- 문제가 없다면 위치 정보를 만들지 말고 발견한 문제가 없다고 명확하게 설명한다.
- 검토가 끝나면 사용자의 다음 지시를 기다린다.
