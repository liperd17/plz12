# Test All

프로젝트에 준비된 전체 테스트를 실행하고 결과를 확인한다.

## 작업 절차

1. AGENTS.md와 프로젝트의 테스트 환경을 확인한다.
2. 프로젝트에 준비된 자동화 테스트를 모두 실행한다.
3. 프로젝트 빌드가 정상적으로 완료되는지 확인한다.
4. 테스트와 빌드 결과를 구분한다. 실패하거나 실행되지 않은 항목이 있으면 오류 메시지와 관련 로그를 확인하고 원인을 분석한다.
5. 전체 결과를 정리하여 사용자에게 보고한다.

## 테스트 결과 형식

### 테스트 결과
- 실행한 테스트
- 성공한 테스트
- 실패한 테스트
- 테스트 자체가 실행되지 않은 경우 그 사실과 확인된 이유

### 빌드 결과
빌드 성공 여부를 테스트 결과와 구분해 설명한다. 빌드가 실패하면 실패한 실행 명령, 실제 오류 메시지와 관련 로그, 확인 가능한 기대 결과와 실제 결과를 포함해 원인을 분석한다.

### 발견한 문제
실패 또는 실행 불가 항목마다 다음 정보를 작성한다.

#### [실패한 테스트 또는 실행 항목]
- **실패 대상:** 실패한 테스트 이름과 테스트 파일, 또는 실패한 실행 명령. 테스트가 시작되지 않았다면 해당 사실을 명시한다.
- **오류 및 로그:** 실제 오류 메시지와 원인 분석에 필요한 관련 로그
- **기대 결과와 실제 결과:** 테스트 코드, 명령 또는 로그에서 확인 가능한 경우에만 기재하고 확인 근거를 밝힌다.
- **확인된 사실:** 출력, 테스트 코드, 설정 또는 프로젝트 파일에서 직접 확인한 내용
- **추정 원인:** 원인이 확정되지 않았다면 추정임을 명확히 표시한다. 원인을 판단할 근거가 부족하면 `판단 불가`로 남긴다.
- **문제 구분:** 코드 문제 / 테스트 코드 문제 / 환경·설정 문제 / 판단 불가 중 근거에 맞는 항목
- **해결 방법 및 추가 확인 순서:** 원인별로 권장 해결책과 재현 또는 판별에 필요한 다음 확인 단계

여러 실패가 같은 원인으로 보이더라도 각 실패의 근거를 확인한다. 공통 원인으로 묶을 직접적인 근거가 부족하면 각각 별도로 보고하고, 공통 원인은 추정으로 표시한다.

실패나 실행 불가 항목이 없으면 원인 분석 대상을 만들지 말고 문제가 없다고 명확히 알린다.

### 최종 의견
프로젝트의 테스트 및 빌드 결과를 종합하여 설명한다.

## 규칙

- 테스트 과정에서 게임 코드를 임의로 수정하지 않는다.
- 실패한 테스트를 임의로 삭제하거나 건너뛰지 않는다.
- 실제로 실행하지 않은 테스트를 성공했다고 보고하지 않는다.
- 테스트 환경 문제와 코드 문제를 구분하여 설명한다.
- 실제 오류 메시지와 로그를 보존해 요약하고, 로그에 없는 기대 결과나 원인을 사실처럼 만들지 않는다.
- 실패 원인이 불확실하면 추정 또는 판단 불가로 명시하고, 확인된 사실과 구분한다.
- 테스트 실패와 빌드 실패를 별도 항목으로 분석한다. 테스트가 실행되지 않은 경우 실패와 구분해 보고한다.
- 문제가 발견되면 수정 방법을 제안하되 직접 수정하지 않는다.
- 테스트가 끝나면 사용자의 다음 지시를 기다린다.
